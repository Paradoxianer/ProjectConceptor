Detailed Description

Isolates the SIGFPE from issue #114 - debug_server caught it inside MessageXmlWriter::ProcessMessage(), 5/5 reproduced at the exact same offset (a deterministic arithmetic fault, not corruption-dependent scheduling), but the exact trigger was never confirmed. Each test here tries one specific candidate field in isolation through the public WriteTo() API (an in-memory BMallocIO destination, no filesystem needed) - whichever one actually faults confirms the real cause.
